# Oracle Review

## Summary

Cam, the changes move UI automation toward RS/1-first behavior: `batch` now accepts structured `elementRef` tap steps, successful `tap`/`batch` preserve same-screen snapshots, parse/empty/debugger failures avoid clobbering the runtime snapshot store, `snapshot_ui` emits more conservative next-step hints, session defaults are filtered before strict validation, and AXe can resolve from a source checkout for validation. I found two high-confidence behavior issues worth fixing before handoff.

## Findings

### P1

- **`src/mcp/tools/ui-automation/batch.ts` — switch batch steps silently drop `preDelay` / `postDelay`**
  - **What’s wrong:** `resolveBatchSteps` intentionally skips `preDelay` and `postDelay` for switch refs because switches are translated into `touch --down` / `touch --up` steps. The schema still accepts those delays, and validation notes show structured batch calls using `postDelay`. This means callers can request settling delays for switch-heavy batches, but the emitted AXe batch ignores them.
  - **Why it matters:** This can make the optimized E2E path flaky: settings toggle batches may execute too quickly even though the caller asked for per-step delay.
  - **Suggestion:** Either encode equivalent delay semantics for switch batch steps if AXe batch supports it, or reject `preDelay` / `postDelay` for resolved switch refs with a clear validation/recoverable error. Don’t silently discard accepted input.

- **`src/mcp/tools/ui-automation/wait_for_ui.ts` — `gone` with both selector fields and `text` ignores `text`**
  - **What’s wrong:** The schema now allows `text` for `gone`, but the runtime only handles text-aware `gone` when no selector is present. If a caller passes something like `{ predicate: "gone", role: "text", text: "Loading" }`, `selector` is set and execution falls through to `evaluateElementPredicate`, where `gone` only checks whether any selector candidates exist and ignores `text`.
  - **Why it matters:** This is a contract trap: accepted input behaves broader than requested and can time out incorrectly or wait for unrelated elements to disappear.
  - **Suggestion:** Either reject `gone + text` when selector fields are also provided, or implement selector-scoped text filtering so the predicate succeeds when no selector-matching candidates contain the text.
